## v1.7.34 — Concurrent ledger writes

### English

Fixes #168: web and headless processes sharing the same `DSH_HOME` could overwrite each other's ledger. A long-running web process could erase newer sessions even after the headless processes had finished.

- A cross-process lock now protects the complete read, merge and atomic write. Each writer uses its own temporary file. Locks left by exited processes are recovered; live writers retain their locks.
- Pending calls are applied to the latest ledger, including updates to the same session, anonymous calls, daily/provider/model totals and plan hourly buckets. Repeated saves do not count those calls again.
- Daily totals remain complete when old session details have been pruned at the 200-session limit. Plan samples are merged, deduplicated and bounded. Independent settings changes and overlapping historical imports are merged.
- Clearing history records a reset marker so stale processes cannot restore old history. Calls recorded after the reset can still be saved.
- An unreadable or malformed ledger is not overwritten during a save; pending changes remain available for retry.

### 中文

解决 #168：共享同一个 `DSH_HOME` 的 web、headless 进程会互相覆盖账本；即使 headless 已退出，常驻 web 进程仍可能在后续保存时抹掉新会话。

- 用跨进程锁保护完整的读取、合并和原子写入，每个写入者使用独立临时文件。自动恢复已退出进程留下的锁，不按持锁时间抢占活跃进程。
- 将待保存调用合并到最新账本，覆盖同一会话追加、匿名调用、每日/厂商/模型合计及套餐小时桶；重复保存不重复计数。
- 会话明细达到 200 条后，每日合计仍保留全部用量；套餐样本按时间合并、去重和裁剪。保留配置的独立修改，并合并重叠的历史导入。
- 清空历史时写入重置标记，防止旧进程恢复此前的历史；重置后记录的新调用仍可保存。
- 保存期间遇到无法读取或格式损坏的账本时，不用内存快照覆盖文件，保留待保存变更重试。

### Upgrade / 升级

Stop the running DSH processes, update every profile that has the plugin installed, then restart them. For web and headless:

先停止正在运行的 DSH 进程，在所有已安装插件的 profile 中升级，再重新启动。例如 web 与 headless：

```sh
dsh plugin --profile web add dsh-cost-meter@1.7.34
dsh plugin --profile headless add dsh-cost-meter@1.7.34
```

Old running versions do not participate in the new locking protocol. Refresh the browser after restarting web.

仍在运行的旧版本不会使用新的写入锁。重启 web 后刷新浏览器。

To recover missing sessions, use **Import pre-install history** in the usage settings while the original DSH session logs are still available. Removed logs cannot be replayed; this update does not recreate missing source data.

如需补回丢失的会话，可在用量设置中使用**导入安装前历史**，从仍存在的 DSH 会话日志补回记录。已清理的日志无法回放，本次升级不会凭空恢复缺失的原始数据。

### Validation / 验证

The regression suite starts eight independent Node processes from the same ledger snapshot and verifies that all 64 new calls survive, including their shared session and anonymous usage. It also covers stale web saves, hourly buckets and samples, session retention, overlapping imports, reset markers, failed-save retry and lock recovery.

回归测试让八个独立 Node 进程从同一账本快照开始写入，验证 64 次新增调用全部保留，包括共同会话和匿名用量；同时覆盖常驻 web 保存、套餐小时桶与采样、会话保留上限、重叠历史导入、重置标记、写入失败重试与锁恢复。
