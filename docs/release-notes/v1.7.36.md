## v1.7.36 — CommandCode quota response compatibility

### English

Contributor PR #176 fixes CommandCode quota queries that fail with “response could not be read as valid JSON” inside DSH 0.1.7. The reporter traced the failure to a CDN response containing compressed bytes without a `Content-Encoding` header. Node fetch cannot decode a response whose encoding is not declared.

`fetchWithRetry` now sends `Accept-Encoding: identity` when the caller has not chosen an encoding. This requests plain JSON from affected CDN edges. An explicit `Accept-Encoding` value remains unchanged. The fix applies to the plugin's quota and balance requests that use the shared fetch helper.

The contributor reproduced the compressed response under the DSH 0.1.7 undici dispatcher and confirmed that the patched request returns parseable CommandCode credits. The repository regression suite checks the default header, explicit overrides and existing fetch behavior.

Issue #174 is also closed: its reporter confirmed that v1.7.35 restored GLM quota data inside the DSH host after restart.

### 中文

贡献者 PR #176 修复 DSH 0.1.7 宿主中的 CommandCode 额度查询报“响应无法读取为有效 JSON”。报告者确认，CDN 返回了压缩字节，却没有提供 `Content-Encoding` 响应头；Node fetch 无法知道正文需要解压。

`fetchWithRetry` 在调用方未指定编码时发送 `Accept-Encoding: identity`，让受影响的 CDN 返回明文 JSON。调用方显式指定的编码保持原样。使用该请求函数的额度和余额查询都采用此默认值。

贡献者使用 DSH 0.1.7 的 undici dispatcher 复现压缩响应，并确认修复后的请求可解析 CommandCode 额度。仓库回归测试检查默认请求头、显式覆盖和原有重试行为。

#174 也已关闭：报告者确认重启后 v1.7.35 已在 DSH 宿主进程内恢复 GLM 额度数据。
