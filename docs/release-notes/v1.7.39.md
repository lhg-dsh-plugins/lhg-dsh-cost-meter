# v1.7.39 — 额度缓存与计费稳定性修复

本次补丁修复余额、订阅额度与账本的几个边界问题：

- 网关额度在有效期内复用缓存，首次并发读取共享请求；刷新失败保留上次成功额度，无关设置修改不清空缓存。
- 自定义余额修改地址、请求内容、条目顺序或启用状态后更新缓存。官方余额、OpenCode Go、订阅额度及自定义余额在关闭查询或卸载时取消失效请求，旧响应不能覆盖新状态；修改订阅凭据后立即作废旧缓存。显示币种转换仍复用原始余额快照。
- 修复超过 1024 个会话后包装路由转发重复计费，并清理过期的会话指纹。
- 格式错误但能解析的账本（如 `null`）保留原文件并恢复写入；外部用量拒绝不存在的日历日期和错误的 `sources` 结构。

新增 14 组针对性回归。完整回归和真实宿主热安装、卸载及重新挂载检查已通过；客户端构建为 262,115 字节，符合 256 KiB 上限。

## English

This patch fixes quota caching, request lifecycle handling, and billing edge cases:

- Gateway quota polling reuses valid cache entries and concurrent initial requests. Failed refreshes retain the last successful quota, and unrelated settings changes preserve the cache.
- Custom balance caches follow endpoint, request, ordering, and enablement changes. Invalidated balance and subscription requests are cancelled, and late responses cannot overwrite current state. Credential updates invalidate the affected subscription cache. Currency display changes continue to reuse the original balance snapshot.
- Wrapper forwarding remains deduplicated after 1,024 sessions, and expired session fingerprints are cleaned up.
- Structurally invalid ledger JSON is preserved before recovery so future writes can proceed. External usage snapshots reject impossible calendar dates and invalid source containers.

Validation includes 14 new regression groups, the full suite, real-host hot installation and lifecycle checks, and the client build. The client remains within the 256 KiB file limit.
