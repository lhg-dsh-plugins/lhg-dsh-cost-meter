# 上下文联动与摘要断流排查

对应反馈：[@nico-zhuang，#279](https://github.com/Han-1413141/dsh-cost-meter/issues/279)。该反馈确认开启联动时发生连续摘要断流，没有证明插件与断流存在因果关系。

1.8.29 将联动的同步 tokenMeter.measure 和会话历史扫描推迟到 LLM 流结束后执行。生成或摘要期间返回上次结果；没有缓存时显示等待提示。插件不更改摘要内容、请求、AbortSignal、上下文上限或重试策略，不额外发送模型请求。流正常结束、抛错、提前关闭和并发请求都有释放检查。

断流时宿主输出带有 `[dsh-cost-meter] stream interrupted` 的诊断行，仅记录错误类型，不写错误正文、提示词、请求头、工具参数或密钥。该行表示上游流向下抛错，不能单独证明错误来自插件。未抛错的正常提前关闭不会被记为错误。

如果更新后仍发生，记录以下内容即可：DSH、dsh-context、dsh-cost-meter 版本；时间和时区；模型及供应商；摘要开始、断流、最终超限的先后关系；上述诊断行和同一时间的宿主错误。先删除 Key、Cookie、Authorization、URL 查询参数、账户标识、会话正文和本机私有路径，再提交到原 issue。不要上传整个账本或会话日志。

可在已有故障会话中比较开启与关闭联动的表现；不需要为了排查额外发起付费请求。上下文已超限时需按宿主提供的恢复操作处理，费用插件不会自行删除上下文或重试摘要。
